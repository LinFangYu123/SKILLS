# 台账结构与格式

已确认问题按「语言 / 分类」两维分文件存放：

```
references/ledger/
├── README.md                 # 本文件:唯一的格式与规则说明
├── python/                   # 每语言一个目录(与语言清单同名)
│   ├── api-design.md         # 每分类一个文件(按需创建,不预建空文件)
│   └── error-handling.md
├── golang/
│   └── concurrency.md
└── general/                  # general.md 兜底清单覆盖的文件(shell/配置等)
    └── dead-code.md
```

## 规则

- **合并优先**：新问题先在同文件内按「模式」查重；命中则累加次数、
  追加例证、更新日期，不新增行
- **模式**写问题的本质（剥离具体文件/变量名），例证才写具体位置
- 某模式累计 ≥5 次时，在模式列加「⚠ 高频」，后续 review 优先检查
- 被后续事实证明为误报的条目，整行删除并在提交说明中注明理由
- 分类文件内条目按「最近发现」倒序，最新问题在最上方便于快速回顾

## 分类文件模板

新建 `<分类>.md` 时使用以下骨架（`# <分类标签> — <语言>` 一行标题
+ 表头，不加其他说明文字）：

```markdown
# <分类标签> — <语言>

| # | 模式 | 严重度 | 已知例证 | 次数 | 首次发现 | 最近发现 |
|---|------|--------|----------|------|----------|----------|
```

- 严重度：🔴 缺陷/安全 / 🟡 隐患/坏味道 / 🔵 风格/可维护性
- 例证：`路径:行号`，多个用 `;` 分隔，最多保留最近 5 个
- 编号 #：文件内自增，删除条目后编号不复用
