# 技能写作指南（写作理论）

写任何给 agent 消费的文档都通用的杠杆：技能、AGENTS.md、被指针引用的
参考文件。核心洞察：**agent 每次运行走的是同一个流程，所以文档的目标
是让流程可预测，而不是让产出千篇一律**。

参考设计：mattpocock/skills@writing-for-agents（本文件是其理论的中文提炼，
概念归属原作者）。

---

## 上下文指针（context pointer）

凡是「留在 agent 上下文里、指向上下文之外的材料」的引用都是指针：
技能的 `description` 是，SKILL.md 里「格式见 xxx.md」的一行也是。

**指针的措辞决定触发时机和可靠性**——同样的目标，措辞弱就是方差 bug，
先磨措辞，磨不好才考虑把材料内联进主文件。好指针做两件事：

1. 说清材料**是什么**
2. 列出**应该触发它的分支**（branch = 文档处理的一个独立情况）

永远加载的指针每个词都常驻上下文，修剪要更狠：

- **触发词前置**：指针的职责就是触发，触发词放最前面
- **一个分支一个触发词**：同义改写是同一分支写两遍，合并之，只留
  真正不同的分支
- **砍掉正文已能自明的身份信息**

## 两种负载

每加一份文档、每写一行指针，都在花两种预算之一：

| 负载 | 花在谁身上 | 例子 |
| --- | --- | --- |
| **上下文负载** | agent 的窗口 | AGENTS.md 的行、技能 description——每轮都占 token 和注意力 |
| **认知负载** | 人类的脑子 | 「有哪些文档、何时该用哪个」——人是索引 |

通过指针才能到达的材料，逃掉上下文负载、只付指针那一行的钱；
完全没有指针的材料，全靠人类的认知负载扛着。

## 信息层级

文档内容由两类构成：**步骤**（有序动作）和**参考**（按需查阅的定义/
规则/事实）。核心决策是每块内容放在层级的哪一级——按「agent 多急需」
排 ladder：

1. **文件内步骤**：主层级，agent 按序执行的内容
2. **文件内参考**：按需查阅，平铺一组是正当安排，不是坏味道
3. **披露参考**：推出主文件、由指针守门、命中才加载

- 推下去太少 → 顶部臃肿；推下去太多 → 藏住了 agent 真需要的东西。
  这个张力就是全部决策
- **渐进式披露** = 沿层级下移，保住顶部的可读性——本质是层级保护，
  不只是省 token
- **披露的判据是分支**：每个分支都需要的内联，只有部分分支才碰到的
  推到指针后面
- **就近原则（co-location）**：同一层内，一个概念的定义/规则/注意事项
  收在同一个标题下，别散落——文档读起来应该像「写给 agent 的文档」
- **失控（sprawl）**是失败模式：每行都有效但文档太长，注意力摊薄。
  药方还是层级：参考推到指针后，按分支/顺序拆文件

## 步骤与完成判据

每个步骤以**完成判据**收尾——告诉 agent「怎样算做完了」。两个杠杆：

- **清晰度**：agent 能分辨 done 和 not-done 吗？模糊的判据（「达成
  共识」）诱发**过早完成**。防御顺序：先磨判据（局部、便宜）；实在
  模糊且观察到抢跑，再靠拆文件把后面的步骤藏出视野
- **需求量**：判据要求多少。「每条改动的规则都被覆盖到」比「列出
  改动清单」逼出更彻底的工作

最强的判据**既可检验又求完备**。

## 引导词（leading word）

引导词是模型预训练里已有的紧凑概念，agent 在执行文档时用它思考
（_tracer bullets_、_雾中行军_）。以 token 的形式重复、从不写成句子，
它就累积出分布式定义，用最少的 token 锚定一整片行为。

- 优先用**已有词汇**而非生造词：生造词不带预训练先验，省下的 token
  要花在定义上
- 找机会把三处展开的表述折叠成一个引导词：
  「快速、确定性、低开销」→ _紧凑_（一个紧凑的循环）
- **否定是相邻的失败模式**：「别想大象」会让大象占满上下文——禁令
  半读起来像是在叫你做那件事。**用正面表述**：说「写单行注释」，
  而不是「不要写长注释」。禁令只留给无法正面表述的硬护栏，且并排
  写出正面目标

## 修剪纪律

- **单一事实源**：一个含义只在一处权威存在，改行为 = 改一处
- **环境也是事实源**（package.json 的 scripts、目录结构、`--help` 输出）。
  复述环境的文档是**缓存**：只有当查询本身昂贵时才值得——写 agent 查
  不到的东西：没写下来的约定、选择背后的理由、配置文件不会自首的坑
- **逐句查相关性**：这行还对文档要做的事有用吗？失效就删。没有修剪
  纪律，文档的默认命运是**沉积岩**——因为加感觉安全、删感觉危险，
  一层层过期内容沉下去
- **逐句查 no-op**：模型默认就会照做的指令，付了负载什么也没买到
  （「要彻底」在 agent 本来就彻底时是空话）。测试是「相对于默认行为
  有没有改变」——没有就整句删除，别修修剪剪留半句
