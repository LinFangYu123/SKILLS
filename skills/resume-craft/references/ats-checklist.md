# ATS 检查清单

Phase 4 逐项过本文，输出结构化检查报告。

## 背景

多数简历在被人类看到之前先被 ATS（机器筛选系统）解析和打分。ATS 挂掉的常见原因：格式解析失败、缺 JD 关键词、标题非标准、文本在图片里。

## 格式规则

**必须做**：
- 交付格式：PDF（文本型，非扫描图）或 DOCX
- 单栏布局；标准字体（中文用黑体类/宋体类，英文 Arial/Calibri/Georgia/Times New Roman）
- 正文 10~12pt，标题 12~16pt，姓名 16~20pt
- 联系方式放正文第一屏，不放页眉页脚
- 标准圆点（•、-）做列表；日期格式全文统一（YYYY.MM 或 MM/YYYY）
- 标准段落标题（机器靠标题识别段落）：工作经历/Work Experience、项目经历/Projects、专业技能/Skills、教育经历/Education

**禁止**：
- 表格、文本框、多栏排版（解析顺序会乱）
- 页眉页脚放关键信息（很多 ATS 不读）
- 图片/图标/技能进度条承载信息（文字进不了解析器）
- emoji、生僻符号做项目符号

## 关键词匹配流程

1. 从 JD 提取必需关键词（硬技能/软技能/行业术语三列，见 SKILL.md Phase 1）
2. 对简历做逐词核对：精确命中 / 近义命中（如"风险规避" vs JD 的"风险管理"）/ 缺失
3. 评分：`命中数 / 必需关键词总数 × 100`，目标 ≥80%
4. 缺失关键词的落位优先级：摘要 > 技能栏 > bullet；落不进任何位置且又不真实掌握的，如实报告留给用户决定

## 关键词密度

- 关键词在全文出现 2~4 次（摘要+技能栏+bullet 各一）足够
- 堆砌（同词反复罗列）会被降权，也伤人类可读性

## 报告格式

```markdown
# ATS 兼容性报告

## 总分：X/100（目标 ≥80）

### 格式检查
- ❌/✅ 逐项列格式规则命中情况，每项附修复动作

### 关键词对照
- ✅ 精确命中：词（出现 N 次）
- ⚠️ 近义命中：简历词 → JD 词（改写建议）
- ❌ 缺失：词（建议落位：摘要/技能栏/某条 bullet）

### 修复后预估匹配分：Y%
```

判据：报告里每个 ❌ 都有已落实的修复动作；修复后重新评分。
