# 技术岗简历结构

起草新简历或调整整体结构时读本文。

## 段落顺序

1. 联系方式（含 GitHub——技术岗必备，放正文不放页眉）
2. 求职意向/摘要（可选，3~4 句：年数 + 方向 + 最重要的技术关键词）
3. 工作经历（倒序；应届/实习不够则项目经历前移）
4. 技能栏（ATS 关键词主阵地）
5. 项目经历（突出规模、难点、个人角色）
6. 教育经历（社招压缩到 1~2 行；应届可提前）
7. 证书（仅与岗位相关的）

## 技能栏组织

按类别分组，别按熟练度自评堆砌：

```
语言：C（5 年）、Python、Shell
系统：Linux 用户态/内核态协同、多进程多线程、epoll
领域：TCP/IP 协议栈、组播路由、高可用（NSR/ISSU）
工具：Git、GDB、Wireshark、NETCONF/YANG
```

- 熟练度用事实表达（年限、生产使用规模）优于"精通/熟悉/了解"自评
- "了解"级条目放在最后，数量控制——全是"了解"的技能栏是负资产
- 每一项都要经得起面试追问，写之前过一遍真伪红线

## 页数与版面

| 年限 | 页数 |
| --- | --- |
| 0~5 年 | 1 页 |
| 5~15 年 | 1~2 页 |
| 15 年以上 | 2 页（至多 3） |

- 版面密度靠内容撑：删社团经历、通用自我评价这类低信息模块
- 一页纸的判据：10 秒扫读能让 HR 说出"这个人会什么、最强的一条经历是什么"

## 技术岗 HR 看什么（按优先级）

1. 相关技术栈是否命中 JD
2. 规模与影响力（用户量/数据量/代码量/团队规模）
3. 解决难题的证据（性能数字、故障恢复、架构决策）
4. GitHub/开源作品（有真实内容才放链接）
