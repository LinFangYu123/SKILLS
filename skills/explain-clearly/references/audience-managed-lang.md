# 受众：托管语言工程师（Python / Java / Go / C#）

读者画像：熟悉带运行时和自动内存管理的语言，可能写过并发（线程池、async），
但多半没碰过手动内存管理、头文件、链接期符号解析、位级内存布局。**触发表述：**
「讲给 Python/Java/Go 的人」「解释给后端同事」。

## 语气校准

- 可直接使用：对象、引用、GC、异常栈、字节码、类与接口、协程、线程池。
- 不要解释「什么是垃圾回收」——他们每天都在用，讲的是**它的代价和替代方案**。
- Go 用户熟悉静态链接的单一二进制，Java 用户熟悉 JVM 与字节码，Python 用户熟悉解释器与 C 扩展。按具体语言选少量锚点，不确定就不选。
- 技术术语保留英文原文。

## 类比池

| 新概念 | 挂靠到 | 必须同时说明的差异 |
| --- | --- | --- |
| 指针 | 对象的引用，但**可以解引用、做算术、指向已释放内存** | 引用是「自动解引用的指针」，且永不悬垂；指针没有这层保护 |
| 栈与堆 | 栈帧与 GC 堆 | C 的栈上可以放整个结构体、生命周期由作用域决定；Java 的栈上只有引用和原始值 |
| `malloc` / `free` | `new` 但没有 GC | 释放时机由人决定，所以性能可预测，泄漏和重复释放也由人负责 |
| 悬垂指针 / use-after-free | Java 里理论上不可能出现的事 | 它是 C 的一大类安全漏洞来源，也是 Rust 所有权系统要消灭的目标 |
| 缓冲区溢出 | 数组越界访问**没有边界检查**的后果 | Java 会抛 `ArrayIndexOutOfBounds`，C 会静默改写相邻内存 |
| 未定义行为 | 托管语言里几乎不存在 | 最接近的是数据竞争，但 UB 更糟：编译器可以假设它从不发生来优化 |
| 编译与链接 | `javac` + JVM 加载 / `go build` | C 的头文件是**文本包含**，符号解析发生在链接期；Go 静态链接成单一二进制，没有动态符号解析 |
| 导出的公开接口 | Java 的 `public`、Go 的大写首字母 | C 没有可见性关键字，靠头文件和约定；私有性只是「不写进头文件」 |
| 宏与预处理 | 注解处理器 / 代码生成 | 宏是**文本替换**，在语法分析之前，因此没有类型检查 |
| 泛型与模板 | Java 泛型（擦除）或 Go 泛型 | C++ 模板是编译期代码生成，会产生多份实例，膨胀二进制 |
| 虚方法与 vtable | 每个对象带类指针，方法查表分发 | 机制几乎一致；C 里没有内建虚方法，要手写函数指针表 |
| 引用计数 / 分代 GC | 对照 CPython 的引用计数与 JVM 的分代收集 | 引用计数的代价在**每次赋值**，分代 GC 的代价在**周期性暂停** |
| 固定宽度整数 | Java 的 `int` 恒为 32 位 | C 的 `int` 宽度随平台变，跨平台传输要显式用 `stdint.h` 的定宽类型 |
| 大小端 | `ByteBuffer.order()` | 托管语言多数默认统一为网络序，C 里结构体布局直接受它影响 |

## 失效边界

- 用「引用」讲「指针」会在算术和生命周期两点失效，这两点恰恰是 C 的关键，必须显式讲。
- 不要用 GC 的思路推测 C 的性能特征：C 没有暂停，但延迟分布由分配模式决定，二者不可互相类推。
