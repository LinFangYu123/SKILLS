# Resume Craft（简历打磨）

以一份**主简历（master）为事实源**，针对目标岗位产出定制版简历。
核心原则：**定制 = 重排与强调真实经历，不是编造**。

## 何时使用

- 用户给出简历（PDF/DOCX/MD/HTML）+ 目标岗位 JD，要求"定制/匹配/投这个岗位"
- 要求"优化简历""改 bullet""加量化数据""ATS 检查/机器筛选过不过"
- 从零起草简历（先走素材盘点，素材不足时向用户追问）

## 不适用

- 只是想总结/朗读简历内容 → 用 content-summary
- 没有目标岗位的泛泛润色 → 仍可用本技能，跳过 JD 分析阶段，按技术岗通用结构改写

## 真伪红线（全程适用）

允许：重排真实信息、强调相关经历、把模糊表述写具体、使用 JD 中的标准术语。
禁止：添加没掌握的技能、篡改数字、虚构经历/头衔/证书。拿不准某条经历是否属实时，问用户，不猜。

## 工作流程

### Phase 0 · 素材盘点

1. 确认三类输入：①主简历或旧简历 ②原始素材（项目文档、工作记录、代码仓库——比简历本身更完整）③目标岗位 JD（没有则记下跳过 Phase 1）
2. 素材比简历详细时，以素材为准重建事实清单：每段经历提取「做了什么 → 怎么做的 → 结果数字」
3. 检查点：能对每一条将写入简历的陈述指出事实来源（文件/用户确认），指不出就删或问

### Phase 1 · JD 分析

从 JD 提取三类关键词，逐类列清单：

- **硬技能**：语言、框架、工具、协议、证书
- **软技能**：JD 实际写出来的（leadership/跨团队协作……），不脑补
- **行业术语**：领域词汇（如网络方向：组播、高可用、转发平面）

然后对主简历做匹配评分：`匹配分 = 命中的必需关键词数 / JD 必需关键词总数 × 100`，目标 **≥80%**。输出：缺失关键词清单 + 近义不精确命中清单（如简历写"风险规避"而 JD 要"风险管理"）。

### Phase 2 · 定制决策

按收益从大到小排：

1. **求职意向/摘要**：镜像 JD 的岗位名与核心要求，含 5~8 个最重要关键词
2. **技能栏重排**：最匹配 JD 的技能放最前，补上真实掌握但漏写的缺失关键词
3. **经历调整**：最相关的 bullet 提到每段经历的第一条；关键词自然融入既有 bullet
4. **取舍**：与目标岗位无关的模块（社团、无关项目）删掉让版面

检查点：定制后的匹配分 ≥80%，且每处修改都能通过真伪红线。

### Phase 3 · 起草与改写

- bullet 写作与量化方法（X-Y-Z 公式、STAR、六类量化维度、弱→强改写）见
  [bullet-writing.md](./references/bullet-writing.md)——凡是要写或改 bullet 的分支都读它
- 技术岗结构（段落顺序、技能分组、页数规则、GitHub 呈现）见
  [tech-structure.md](./references/tech-structure.md)——起草新简历或调整整体结构时读它
- 每条 bullet 的判据：动词开头 + 有具体数字/规模 + 体现结果而非职责。三者缺一即为未完成

### Phase 4 · ATS 检查

逐项过 [ats-checklist.md](./references/ats-checklist.md)（格式规则、标准标题、关键词密度），输出结构化报告：格式问题、关键词命中对照表、修复后的预估匹配分。判据：报告里每个 ❌ 都有对应的修复动作，且修复动作已落实到文档。

### Phase 5 · 产出

本机已验证的管线，直接复用：

1. 写 HTML 源文件（内联 CSS，中文字体 `Noto Sans CJK SC`，A4 友好的 margin）
2. `soffice --headless --convert-to pdf <file>.html` 生成 PDF
3. 用 `pdftotext -layout` 回读验证中文渲染无乱码、`pdfinfo` 确认页数符合 tech-structure.md 的页数规则
4. 版本管理：主简历永远是 master 源文件；定制版按 `<姓名>_简历_<目标岗位>_<公司>.pdf` 命名，master 不被定制版覆盖

检查点：PDF 可打开、中文正常、页数合规、文件名可追溯对应哪次投递。

## 产出物约定

定制过程同步产出一份**修改说明**（含关键词增删清单、before/after 对比、匹配分），用户面试准备时可直接复用。
