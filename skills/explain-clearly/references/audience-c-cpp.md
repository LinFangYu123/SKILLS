# 受众：C / C++03 程序员（默认）

读者画像：会 C 和 C++03（无 `auto` / lambda / move / `nullptr` / `unordered_map`，STL 未系统学过），
没有 JavaScript / Java / Go / Rust 经验，不熟悉现代语言特性。**这是未指定受众时的默认档。**

## 语气校准

- 默认对方是资深 C 程序员，只是没接触过这个具体领域。不解释什么是循环、什么是指针。
- 可直接使用：指针、栈与堆、`malloc`/`free`、结构体、函数指针、位运算、`errno`、`volatile`、`static`。
- 避免使用：智能指针、模板元编程、STL 算法、C++11 及之后的特性、`unordered_map`。
- 缩写首次出现给全称：OOP、GC、ORM、ABI、TTL。
- 技术术语保留英文原文，不强行翻译。

## 类比池

### 语言语义与对象模型

| 新概念 | 挂靠到 | 必须同时说明的差异 |
| --- | --- | --- |
| Python 变量 / 名字绑定 | 指向对象的指针 | 名字本身无类型，像 `void*`，类型信息在对象里；重新赋值只改指向，不改原对象 |
| `dict` | 手写 struct 查找表 / `std::map` | 迭代是**插入序**，不是 key 排序序 |
| `None` | `NULL` | 它是单例对象，不是 0，无隐式数值转换 |
| 异常 | 会自己往上冒的 `errno`，未捕获时行为接近 `abort()` | 没有返回值检查这一步；调用者不写 `if` 也会中断；清理逻辑靠 finally |
| 引用计数式 GC | 手工维护的 `refcount++` / `--` | CPython 在计数归零时**即时**释放，不等到进程退出；循环引用需要额外的收集器 |
| 字符串单 / 双引号 | `'a'` 是 int，`"a"` 是 char 数组 | Python 两种引号**完全等价** |
| 模块导入 | `#include` + 链接 | 导入在**运行时**执行整个文件，且只执行一次，副作用在此发生 |
| 闭包 | 函数指针 + 手工传的 context 结构体 | 捕获的是**变量本身**（引用），不是当时的值拷贝 |
| 装饰器 | 拿函数当参数、返回新函数的函数 | 不是宏，没有文本替换，发生在运行时对象层 |
| 类型注解 | `/* int */` 注释 | 运行时不检查，只给工具和阅读者看 |
| 浅拷贝 / 深拷贝 | `memcpy` 整个结构体 | 指针成员只复制指针，指向的还是同一份数据 |
| 事件循环 / 协程 | `select`/`poll` 循环 + 手写的续体状态机 | 单线程内切换，没有栈复制，靠显式的让出点分段 |
| 共享可变状态 | 两个指针指向同一块 `malloc` 内存 | 赋值不拷贝对象，两个名字改的是同一份数据 |

### 内存、构建与运行时

| 新概念 | 挂靠到 | 必须同时说明的差异 |
| --- | --- | --- |
| 容器 / 镜像 | `chroot` + tar 包 | 镜像是分层只读的，容器在顶层加一层可写层 |
| 虚拟环境 | 换一组 `PATH` 和库搜索路径的 shell 脚本 | 只改解释器看到的东西，不动全局系统 |
| 依赖管理锁文件 | 记下每个依赖确切版本的清单 | 它的价值在于复现，不在安装本身 |
| JIT 编译 | 运行时把中间表示翻成机器码 | 与 AOT 的取舍：启动慢、稳定运行后快，靠 profiling 找热点 |
| ABI | 函数调用约定 + 名字修饰约定 | 跨编译器/版本不保证兼容，这是二进制分发头疼的根源 |

### 系统与基础设施

| 新概念 | 挂靠到 | 必须同时说明的差异 |
| --- | --- | --- |
| 哈希表冲突 | 手写链地址法 + 装填因子 | 装填因子超阈值会扩容，扩容时所有 key 重新分布，这一瞬间代价很高 |
| 数据库索引 | 排好序的索引文件 + 按 key 二分查找 | 需要额外空间和维护成本，写入变慢换取读取变快 |
| 事务 | 一组要么全做、要么全不做的操作 | 崩溃恢复靠日志（WAL），不是靠内存里的临时状态 |
| 乐观锁 | CAS（比较并交换） | 冲突时需要重试整个操作，适合冲突少的场景 |
| 缓存 | 手工维护的查找表 | 真正的难点是失效策略和一致性，不是查得快 |
| 正则表达式 | 手写的字符分类 + 循环匹配 | 回溯可能指数级爆炸，对恶意输入是拒绝服务风险 |
| 消息队列 | 有锁的环形缓冲区 | 跨进程甚至跨机器，没有共享地址空间，所以只能传值 |

### 网络与协议

| 新概念 | 挂靠到 | 必须同时说明的差异 |
| --- | --- | --- |
| REST / RPC 接口 | 函数签名 + 编码约定 | 跨进程、跨机器，没有链接期检查，一致性靠约定和文档 |
| 序列化（JSON / Protobuf） | 把结构体逐字段写进文件 | 要处理字节序、对齐、版本兼容；JSON 是文本且自描述，代价是体积和解析开销 |
| 客户端 / 服务端 | 主从函数调用 | 没有共享地址空间，调用可能失败、超时、重复到达 |
| 负载均衡 | 调度器轮转分配任务 | 要处理有状态请求的粘性问题 |

### 算法与数学

| 新概念 | 挂靠到 | 必须同时说明的差异 |
| --- | --- | --- |
| 时间复杂度 O(n²) | 双层 `for` 循环 | n 翻倍，时间翻四倍；O(n log n) 相当于「每层只处理一半」 |
| 指数 / 对数增长 | 循环里每次乘常数 vs 每次加常数 | 指数增长很快撞到物理上限，所以实际方案都往对数方向设计 |
| 标准差 | 遍历数组求「平均偏离中心多少」 | 它衡量离散程度，不衡量正确性 |
| 相关性 | 两个变量同时变化 | **不等于**其中之一导致了另一个；因果需要额外的机制证据 |
| 利差 | 两个函数返回值之差 | 用具体金额算一遍：100 万本金上 5% 是 5 万 |
| 复利 | 循环里每轮乘一个因子，结果回填下一轮 | 时间一长，指数效应会压过初始差异 |
| 收益率 | 输出与输入的比值 | 要区分「期间总收益」和「年化收益」，两者换算有陷阱 |
| 概率 | 随机数发生器 + 统计计数 | 单次结果不可预测，只有大量重复才有稳定分布 |

## 失效边界

- 拿 C 讲动态语言时，「指针」是比喻不是事实：C 里指针本身有类型、能做算术，Python 的名字两样都不能。走到这两点必须刹车。
- 拿 C 讲托管语言时，GC 的暂停、内存可见性、并发模型都可能与 C 的直觉相反。讲并发时不要沿用「共享内存 + 锁」作为唯一框架，先说明该语言的并发模型是什么。
