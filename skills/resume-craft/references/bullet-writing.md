# Bullet 写作与量化

写或改任何一条简历 bullet 前先读本文。

## 弱 bullet 与强 bullet 的分界

弱：职责导向、被动、无数字——"负责管理团队""参与改进流程"。
强：成就导向、动词开头、有规模有结果——"主导 12 人团队交付 200 万项目，营收提升 35%"。

**职责 bullet 只在两种情况保留**：该职责本身就是成就（"独立负责 XX 模块"），或实在没有结果数据（此时仍要写出规模和方法）。

## 两个改写框架

### X-Y-Z 公式（Google 法）

「达成 [X]，以 [Y] 衡量，通过 [Z] 实现」

- X = 成就；Y = 度量（数字）；Z = 具体做法
- 例：❌"优化了客服体系" → ✅"通过重构工单系统并培训 15 名客服，将满意度从 3.2 提升到 4.5/5"

### STAR 压缩式

完整 STAR（情境-任务-行动-结果）压缩进一句：**行动在前，结果收尾，情境只留必要的定语**。
例："接手达标率 65% 的销售团队，通过培训体系与提成重构，两季度提升至 92%，增收 180 万"。

## 六类量化维度

没有现成数字时按这六类找，任何经历至少能命中一类：

| 维度 | 追问示例 |
| --- | --- |
| 钱 | 省了多少成本？管多大预算？带来多少收入？ |
| 时间 | 周期从多长缩到多短？多少人天？响应多快？ |
| 百分比 | 提升多少？错误率降多少？效率增益？ |
| 规模 | 多少用户/项目/表项/并发？团队多大？多少行代码？ |
| 质量 | 可用性？SLO？通过率？故障率？ |
| 频率 | 日均/月均处理多少？迭代节奏？ |

**挖掘方法**：问"当时如果没有这个改动会怎样"，差值就是结果；问上级/测试/监控报表要原始数字；实在没有精确值就用可靠的估算范围（"约""千级"），不编精确数。

## 关键词融入规则

- 优先用 JD 的原词（ATS 按字面匹配），前提是词义与实际工作相符
- 核心关键词在摘要、技能栏、bullet 里各出现一次即可，不堆砌
- 同一能力可换近义表述分散在不同 bullet（"带领团队"/"团队管理"），避免重复感
