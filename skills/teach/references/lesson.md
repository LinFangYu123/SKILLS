# 讲义（lessons/）

讲义是本技能的主要产出：每节一个自包含 **Markdown** 文件，`lessons/NNNN-<dash-case-name>.md`，编号递增。

用户会反复回来翻它，所以它必须**好看**——干净、可读的排版，印刷出来也体面。目标是 Tufte 那种克制：单栏、宽留白、少色彩、信息密度高而不拥挤。Markdown 天然就克制，别用花哨语法把这份克制破坏掉。

没有构建步骤，没有样式表，没有脚本。任意 Markdown 阅读器（编辑器预览、GitHub、VS Code、Obsidian、`glow`）打开即可。

## 一节课的纪律

- **短，且当次就能读完做完。** 学习者的工作记忆很小。宁可拆成三节，也不要在一节里塞三个主题。
- **一个可拿走的胜利。** 每节课结束时用户必须多出一样**能做的事**，而不只是多知道一些事。
- **紧挂使命。** 讲义开头就写清它服务于 `PROGRESS.md` 里的哪个里程碑。
- **落在最近发展区。** 太浅是浪费时间，太深是挫败。判据：用户读的时候会偶尔卡住，但不需要外部帮助就能过。
- **每节推荐一个一手来源。** 取自 `RESOURCES.md`，用链接指向它，让用户能自己往下走。
- **每节都要提醒"可以追问老师"。** 你是他的老师，任何不清楚的地方都可以问。

## Markdown 骨架

```md
# 0003 · 悲观锁与乐观锁

> 第 3 节 · 里程碑 2：能给出正确的并发方案
>
> 学完这节，你能看着一段并发写入代码，判断该选哪种锁并说出理由。

（正文：核心概念 → 完整示范 → 渐撤练习 → 独立练习 → 自测）

---

**一手来源**：[来源标题](https://example.com/page)

**相关**：[第 2 节 · 事务隔离级别](0002-transaction-isolation.md) · [术语表](../reference/glossary.md)

**没懂的地方直接问我——我是你的老师，追问不用客气。**
```

- 文件名用英文短横线，**标题行**用用户的语言。
- 首行标题带编号（`# NNNN · 标题`），文件名已排序，标题再标一次是为了在阅读器里也能一眼定位。
- 开头那段引用块（`>`）承担"这节课挂在哪 + 学完能做什么"两件事，占位不超过三行。
- 结尾用一条 `---` 分隔，后面依次放一手来源、相关讲义链接、术语表链接、"可以追问"。

## Markdown 方言

只写 **CommonMark + 表格 + 任务列表 + `<details>` 折叠块**。别的语法一律不用：

| 别用 | 为什么 |
| --- | --- |
| `[[wikilink]]` | Obsidian 专有，换阅读器就是死链 |
| `> [!NOTE]` 告警框 | GitHub 专有，别处退化成普通引用 |
| `==高亮==`、`~~删~~` 之外的扩展 | 各家支持不一，渲染结果不可预期 |
| 行内 HTML（除 `<details>`） | 破坏"纯 Markdown"的承诺，也过不了某些渲染器 |

**唯一允许的 HTML 是 `<details><summary>`**，用来折叠测验答案（见下节）——它是 CommonMark 未覆盖、但所有主流渲染器都支持的最小例外。

## 正文结构

按这个顺序写，它是"理解 → 模仿 → 独立"的支架：

1. **开头引用块**：一句话说清学完能做什么。不写"本节介绍……"，写可观察的能力。
2. **核心概念**：一次只讲一个概念。**先平实定义，再绑到具体场景**（"一般情况下它是 X；在我们这个 case 里拿它干 Y"），再讲它怎么工作、为什么这么设计、边界在哪。需要图就按下面的增量图规则来。
3. **完整示范（worked example）**：一个从头到尾做对的例子，每一步都写清**为什么这么做**，而不是只有结果。这是脚手架的第一级。用围栏代码块，注释写在代码里或紧跟其后的列表里。
4. **渐撤练习**：给一个留了一半的同类问题，让用户补完。这是第二级。
5. **独立练习**：一个只给要求、不给步骤的问题。这是第三级，通常紧接测验。
6. **自测**（见下节）。
7. **页脚区**：一手来源、相关讲义、术语表链接、"可以追问"。

写完自查每条：**这一句是在讲知识，还是在帮用户建立技能？** 只有功能列表、没有机制解释的内容是参考资料，放到 `reference/`，不要塞进讲义。

## 排版规范

| 用途 | 写法 |
| --- | --- |
| 提示 / 陷阱 / 旁注 | 引用块 + 行首加粗前缀：`> **注意**：…`、`> **坑**：…`、`> **为什么**：…` |
| 代码 | 围栏代码块 ```` ```lang ````；行内 `` `code` `` |
| 对照 | Markdown 表格——两种以上方案对比优先用表，不用散文 |
| 流程图 / 结构 | ```` ```mermaid ```` 代码块 |
| 空间性图示（布局、重叠、滚动位置、前后对比） | 围栏代码块里的 ASCII 图，或用生图工具画好后以 `![说明](路径)` 引入 |
| 关键定义 | `**术语**：定义` 列表，或 Markdown 表格 |
| 折叠答案 | `<details>\n<summary>看答案</summary>\n…\n</details>` |
| 术语引用 | 链接到 `../reference/glossary.md` |

- **旁注只用三种前缀**（注意 / 坑 / 为什么），不要自造一堆 emoji 标签——标签一多就没人看标签了。
- 两种以上方案比较、参数对照、正反例对照，**一律用表格**，不要写成一串"首先……其次……"。
- 需要外部资源时只引 `RESOURCES.md` 里的来源，并在正文里以链接形式标注出处，让每个断言都能被追溯。
- **图优先用 mermaid 代码块或 ASCII**，不引用图表 CDN、不引入外部字体或 JS：讲义必须能离线打开、能打印。mermaid 不被渲染时，源码本身仍然是可读的结构描述，这是选它的理由。
- 加粗只用于术语、关键结论和引用块前缀。通篇加粗等于没有加粗。

## 练习与测验

自测区由**纯 Markdown + 折叠块**组成：题干与选项在上，答案与解析折叠在每题下方。答对答错由用户自己对答案，因此**零提示**这条硬约束比原来更重要——一旦选项泄露了正确性，折叠就白折叠了。

````md
### 自测

**1.** 写冲突密集的计数器更新，选哪种锁？

- A. 乐观锁
- B. 悲观锁
- C. 不用锁
- D. 读锁

<details>
<summary>看答案</summary>

**B** —— 冲突率高时乐观锁的重试代价按冲突率上升，反而更慢。

</details>

**2.** 下一题……
````

**零提示是硬约束**——每道题只能被真正懂的人答对：

1. 选项描述不得泄露正确性。反例：`悲观锁 —— 适合写冲突高的场景`；正例：`悲观锁 —— 写入前先持有排他锁`。
2. 任何选项都不加"(推荐)"。
3. **打乱正确项位置**，不要总在首位、不要总在同一个字母。
4. 题干问行为/用途/输出，不暗示答案。反例"`error()` 向哪个流输出？"；正例"`error()` 的输出去了哪里？"。
5. 错误选项必须是该领域**真实存在的概念**，而且是常见误解——瞎编的干扰项会让题目变成猜谜。

选项始终用**字母前缀的列表**（`- A. …`），不要用 Markdown 任务列表（`- [ ]`）——那会让人以为要打勾，且答案字母就没法指代了。

题量与难度按场景调（写在讲义里的是自测，通常 3-5 题）：诊断用 40% 易 / 40% 中 / 20% 难；刷弱项用 30% 中 / 70% 难；复习则各档均匀。

**重考弱项概念时换语境**：不要重问原题，换个角度考同一个底层知识。比如用户混了"400 vs 422"，就编一个新场景让他选。

课后对话里的正式测验是 **4 题、每题 4 个选项**，判分后按 [../SKILL.md](../SKILL.md) 分支 2 第 6 步更新 `mastery/` 与 `PROGRESS.md`。

## 插图与旧文件迁移

**插图按需，脚手架不预建 `assets/`。** 真需要图片或附件时再建目录（如 `assets/img/`），用相对路径引入：`![说明](../assets/img/xxx.png)`，并在 `NOTES.md` 里记一句这个约定。纯文字、表格、mermaid、ASCII 能讲清的，就不要配图。

**遇到旧工作区里的 `.html` 讲义：**

- **新写的讲义一律 `.md`**，任何情况下都不要新增 `.html`。
- 已存在的 `.html` **保留不动**，不做批量转换——机械转换会破坏排版，仍需逐节人工校对，收益不如按新规范重写。
- 用户要重看某一节且它是 `.html` 时，说明该节需要重写：按本文件的规范重写为 `NNNN-<slug>.md`，删掉旧 `.html`，并把引用它的链接（`PROGRESS.md`、其他讲义的"相关"行）一并改掉。
- 术语表同理：`reference/glossary.html` → `reference/glossary.md`，重写时按 [./formats.md](./formats.md) 的术语表格式。
